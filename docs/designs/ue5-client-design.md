## 1. 아키텍처 결정: C안 — UE5 클라이언트 / C# 로컬 시뮬 서버

```
┌─────────────────────┐  localhost HTTP+JSON   ┌──────────────────────────┐
│ UE5 클라이언트 (신규) │ ◄──────────────────── │ C# 게임 서버 (기존 Core)   │
│ 지도 렌더·명령 UI·연출 │  상태 스냅샷+이벤트 저널  │ 전투·가챠·AI·세이브·161테스트│
│ 로직 0 [MUST]        │ ────────────────────► │ + ApiServer (server 모드) │
└─────────────────────┘   명령(seq 멱등)        └──────────────────────────┘
        └─ 자식 프로세스 스폰 (Job Object KILL_ON_JOB_CLOSE, 포트 0 + stdout 핸드셰이크)
```

**기각 사유 요약** — A(C++ 풀 포팅+오라클): 이중 SSOT 영구화, 밸런스 변경마다 양쪽 수정+비트 동일성 재검증, 첫 픽셀까지 수개월, AI 단독 UBT 컴파일 루프 최악. 원안 오라클은 "재미검증 후 상업 수준 이식" 전제였고 영구 가족 전용 현실과 불일치. B(UnrealSharp): 서드파티 플러그인에 수년 프로젝트 생존 종속 — 단일 실패점.

**채택 근거**: 로직 포팅 0(161 테스트·세이브 계약 D1-D10·결정론 그대로), 턴제라 localhost 지연 무의미, HttpListener 패턴은 밸런스 패널로 기검증, UE 설치 전 API 완성 가능, UE 좌초 시에도 콘솔 폴백 무손상.

## 2. 프로토콜 계약 (API v1) — 적대 검증 완화책 전량 반영

### 2.1 원칙
- **전체 상태 스냅샷** 모델 (세밀 RPC 아님): 턴제라 스냅샷 비용 무시 가능, 계약 변경 빈도 최소화.
- **계약의 정본 = C# DTO 타입** (ApiDtos.cs). 클라이언트는 소비만. 기동 시 프로토콜 버전 핸드셰이크.
- 응답에 `status` 예약: `ok | error | need_input` (향후 전투 중 상호작용 확장 경로).

### 2.2 엔드포인트
| 메서드 | 경로 | 역할 |
|---|---|---|
| GET | `/api/info` | 프로토콜 버전·게임 상태 유무 핸드셰이크 |
| POST | `/api/new` `{p1, p2?, seed?}` | 새 캠페인 (p2 없으면 solo) |
| POST | `/api/load` / `/api/save` | 세이브 왕복 (기존 SaveSystem) |
| GET | `/api/state` | 전체 상태 스냅샷 (§2.3) |
| GET | `/api/static` | 불변 정의: 맵(노드+map_pos+간선)·세력·캐릭터·병종 표시 정보 |
| POST | `/api/command` `{seq, faction, verb, args}` | 명령 실행 → `{status, message, events[], state}` |
| GET | `/api/events?cursor=N` | 이벤트 저널 재동기 (유실 복구) |
| POST | `/api/shutdown` | 명시적 종료 |
- 밸런스 패널(`/panel/*`)도 **같은 서버에 통합** — 포트 단일화. 데이터 리로드는 캠페인 경계에서만(`/api/reload-data`는 메뉴 상태 한정).

### 2.3 상태 스냅샷·이벤트 저널·멱등성
- 스냅샷: turn·phase·actor·faction별(자원·천명·pity·외교)·province 소유/시설·armies·fleets·characters 소속/게이지 + `pending = 어느 세력의 입력 대기인가`.
- **이벤트 저널**: EventBus 구독으로 `(campaignId, seq)` 부여해 축적. 명령 응답에 신규 events[] 동봉 + cursor 재동기. 캠페인마다 Bus/GameManager 새로 생성(구독자 누적 차단). 컷씬·전투·가챠 리빌이 전부 이벤트로 흐름 — 연출-상태 괴리 차단.
- **명령 멱등성**: 클라 단조 `seq` 부착, 서버는 중복 seq에 캐시된 원 응답 재전송 — HTTP 재시도의 RNG 이중 소모(가챠 이중 뽑기 등) 프로토콜 수준 차단.
- **SessionDriver 를 Core 로 추출**: "다음 입력 대기 지점까지 자동 페이즈 전진"(Income/AiAction/VictoryCheck 통과, 첫 턴 수입 정산 규칙 포함)을 PlaySession 과 ApiServer 가 **공유** — 플로우 이중 구현 금지 [MUST].

## 3. UE5 클라이언트 독트린 (AI 단독 개발 전제)
- **코드-퍼스트 [MUST]**: Blueprint 저작 금지(바이너리 .uasset 은 AI가 읽고 쓸 수 없음). UI = C++ UMG/Slate 코드 생성, 전략맵 = `/api/static`의 노드·map_pos 에서 **절차 생성**(레벨 수작업 없음), 머티리얼 = 소수 베이스 + MaterialInstanceDynamic, VFX = 기본 템플릿 한정.
- **UE 스크린샷 QA 하네스 = 첫 마일스톤 포함**: 고정 시드 서버 기동 → `-game -RenderOffscreen` + HighResShot → AI 이미지 판독 (YUNU_GAME 헤드리스 QA 패턴 이식). AI가 자기 산출물을 볼 수단을 초기 확보.
- **에셋 전략 (IP 벽 회피)**: KOEI풍 2D 초상화 중심. `Content/Portraits/<캐릭터id>.png` 드롭인 + 실루엣 폴백 — 크로스오버 캐릭터(타사 IP) 이미지는 시스템이 요구하지 않고, 파일을 넣으면 뜨는 구조(가족 전용 사적 이용). 3D는 범용 유닛 모델만.
- 서드파티 플러그인 의존 0 — UE 내장 Http/Json 모듈만.

## 4. 프로세스·배포 계약
- UE5 가 C# 서버를 자식 스폰: Job Object(KILL_ON_JOB_CLOSE) 로 고아 차단, 포트 0 바인딩 후 stdout 핸드셰이크로 포트 전달, 기동 헬스체크 실패 시 명확한 에러 + 재스폰 1회.
- C# 서버는 **self-contained 단일 파일 publish 로 전환** — DOTNET_ROOT·.bat 인코딩 의존 제거 (기존 framework-dependent 배포의 한글 경로 함정 해소).
- 개발 중 콘솔 play/solo 모드는 영구 유지 — UE 미완 구간·장애 시 가족 플레이 폴백.
