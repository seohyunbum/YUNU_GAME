# PROJECT WORLD CONQUEST (가칭) — AI 작업지시용 마스터 설계문서

> **문서 버전**: v1.0 (2026-07-16)
> **프로젝트 성격**: 부자(父子) 2인 협동 플레이를 위한 KOEI 삼국지 스타일 대전략 게임. AI(Claude Code 등)와의 협업 개발 전제.
> **저장소 정책**: 본 repo(YUNU_GAME)는 **비공개 가족용 프로젝트**. 타사 IP 캐릭터(귀멸의 칼날·마블·Fate 등)를 등장시키므로 **퍼블릭 공개·상업 배포·외부 공유 절대 금지**. 개인 학습·가족 놀이 목적으로만 사용한다.

## 0. 이 문서의 사용법 (AI에게 지시하는 방법)

본 문서는 **AI에게 개발 작업을 지시할 때 참조시키는 단일 진실 원천(SSOT)** 이다.

### 0.1 준수 레벨 표기

| 표기 | 의미 |
|---|---|
| **[MUST]** | 절대 준수. 위반한 코드는 리젝. AI가 임의로 바꿀 수 없음 |
| **[SHOULD]** | 강력 권장. 어길 경우 반드시 이유를 먼저 보고하고 승인받을 것 |
| **[MAY]** | AI 재량 허용. 단, 선택한 방식을 코드 주석이 아닌 PR/커밋 메시지에 기록 |

### 0.2 AI 지시 시 표준 프롬프트 서두

모든 개발 지시는 아래 문장으로 시작한다:

```
docs/GAME_DESIGN_SPEC.md 를 먼저 읽고, 현재 Phase(§7 참조)의 완료 기준(DoD)을 확인한 뒤 작업하라.
§4 아키텍처 규칙과 §5 데이터 스키마를 위반하는 코드는 작성하지 마라.
이번 작업 범위: <구체 작업>
```

### 0.3 AI가 지켜야 할 작업 원칙 [MUST]

1. **한 번에 한 Phase, 한 모듈만 작업**한다. "전부 다 만들어줘"식 요청이 와도 §7 파이프라인 순서를 안내하고 현재 Phase에 집중한다.
2. 코드 작성 전 **어떤 클래스/파일을 만들지 목록을 먼저 제시**하고 승인받는다.
3. 기존 코드를 수정할 때는 **수정 파일·이유를 한 줄씩 보고** 후 진행한다.
4. 스탯·밸런스 수치를 코드에 하드코딩하지 않는다 (§5 데이터 주도 설계).
5. Phase 3(UE5 연동) 이전에는 **엔진 의존 코드를 한 줄도 작성하지 않는다**.

### 1.1 핵심 플레이 시나리오 (이 게임이 재미있어야 하는 단 하나의 장면)

> 아빠와 아들이 각각 캐릭터와 시작 영지를 고른다. 초반에 동맹을 맺고, 세계 지도의 AI 세력들을 상대로 협공한다. 아들이 육상 대군으로 진격할 때 아빠 함대가 해상에서 상륙전을 열어주고, 위기 순간 각자의 에이스 캐릭터가 화려한 궁극기를 터뜨린다. 최종적으로 세계를 양분하거나, 동맹 공동 승리를 선언한다.

모든 설계 판단은 이 장면을 기준으로 우선순위를 정한다. 이 장면에 기여하지 않는 기능은 후순위 [SHOULD].

### 1.2 2인 협동 설계 요구사항 [MUST]

- **핫시트 턴제**: 같은 PC에서 플레이어1 턴 → 플레이어2 턴 → AI 세력 턴 순서로 진행. (실시간·네트워크 플레이는 스코프 아웃, §9)
- **동맹 전용 메커니즘**:
  - 동맹 세력 간 **시야 공유** (탐사한 영지 정보 공유)
  - **자원 지원** (금·식량 이전, 턴당 상한 있음)
  - **공동 전투**: 같은 영지 전투에 양측 부대가 함께 참전 가능. 이때 각 플레이어가 자기 부대만 조작
  - **통행권**: 동맹 영지·해역 자유 통과
- **공동 승리**: 세계 정복 시점에 동맹이 유지되어 있으면 양측 모두 승리 처리
- **난이도 배려**: 아들 플레이어를 위한 세력별 난이도 보정(자원 보너스, AI 공격성 하향)을 게임 시작 옵션으로 제공 [SHOULD]

## 2. 핵심 게임플레이 설계 (Core Gameplay)

### 2.1 글로벌 맵 — 노드 그래프 시스템 [MUST]

- 세계 지도를 **노드(Node) + 간선(Edge) 그래프**로 표현한다. 타일맵이 아니다.
- 노드 종류:
  - **육상 영지(LandProvince)**: 도시·성. 내정 대상. 인구·시설·수비대 보유
  - **해상 거점(SeaZone)**: 해역. 함대 이동 경로이자 점령 가능한 요충지(주요 해협·항구 앞바다)
- 간선 종류: 육로(land), 해로(sea), **항구 연결(port — 육상↔해상 전환점, 상륙전 발생 지점)**
- 초기 맵 규모 [SHOULD]: **육상 영지 40~60개 + 해상 거점 10~15개** (대륙 6개 권역: 동아시아·유럽·중동·아프리카·아메리카·오세아니아). 전 세계 수백 개 노드는 밸런스 검증 후 확장
- 맵 데이터는 `data/map/world_map.json` 외부 파일 [MUST] (§5.4)

### 2.2 턴 구조 [MUST]

1턴 = 1개월(게임 내 시간). 턴 페이즈 순서:

```
[1] 수입 페이즈   — 전 세력 자원 수입 정산 (영지 Produce)
[2] 플레이어1 페이즈 — 내정 명령 + 군사 명령 + 외교 명령
[3] 플레이어2 페이즈 — 동일
[4] AI 세력 페이즈  — AI 세력들이 순서대로 행동
[5] 해결 페이즈   — 이동 완료 처리, 전투 발생 판정 → 전투 씬 진입
[6] 이벤트 페이즈  — 랜덤/조건 이벤트 (재해, 인재 등용 기회, 반란 등)
[7] 승리 판정    — CheckWinCondition()
```

### 2.3 자원과 내정

| 자원 | 용도 | 획득 |
|---|---|---|
| **금(Gold)** | 병력 유지비, 시설 건설, 등용, 외교 | 영지 상업 + 시장 시설 |
| **식량(Food)** | 병력 유지, 원정 보급 (부족 시 사기 급락) | 영지 농업 + 농지 시설 |
| **병력(Troops)** | 부대 편성 | 영지 인구에서 징병 (인구 감소 트레이드오프) |
| **기술(Tech)** | 병종 해금, 함선 업그레이드 | 학당 시설 + 지력형 캐릭터 배치 |
| **민심(PublicOrder)** | 0~100. 낮으면 반란·생산 페널티 | 정치형 캐릭터 내정, 세율 조절 |

- 영지별 시설 슬롯(기본 4개): 시장 / 농지 / 병영 / 학당 / 성벽 / 항구(해안 영지만)
- 각 시설은 레벨 1~3, 건설·업그레이드에 금 + 소요 턴

### 2.4 캐릭터 시스템

- **캐릭터 = 이 게임의 상품성 핵심.** 역사 위인(이순신, 조조, 나폴레옹 등) + 크로스오버 IP 캐릭터(탄지로, 성진우, 아이언맨, 세이버, 마슈 등)
- 기본 스탯 6종 (1~120):

| 스탯 | 효과 |
|---|---|
| 통솔(LDR) | 부대 최대 병력, 부대 방어 |
| 무력(STR) | 부대 공격, 일기토 |
| 지력(INT) | 계략 성공/회피, 기술 생산 |
| 정치(POL) | 내정 효율, 외교 성공률 |
| 매력(CHA) | 등용 성공률, 사기 회복 |
| 해군(NAV) | 함대 지휘 시 전투력 보정 (이순신 계열 차별화 스탯) |

- **스킬 구조** [MUST]:
  - **패시브 1개**: 상시 발동 (예: 이순신 "불패" — 해상전 방어 +30%)
  - **궁극기(Ultimate) 1개**: 전투 중 게이지 충전 → 발동. 컷씬 + 광역 이펙트 (예: 학익진 = 적 전열 광역 피해 + 아군 해상 사기 상승 / 마슈 "로드 카멜롯" = 아군 전체 3턴 피해 무효 방패)
  - 스킬 효과는 **효과 타입(EffectType) 조합으로 데이터 정의** — 코드에 캐릭터별 if문 금지 (§5.2)
- 성장: 전투·내정 경험치 → 레벨 1~50, 레벨업 시 스탯 소폭 상승
- 충성도: 낮으면 타 세력 등용에 넘어감. 매력·금으로 관리

### 2.5 병종과 상성 [SHOULD]

- 기본 병종: 창병 → 기병 → 궁병 → 창병 (3상성) + 공성병기, 특수병종(캐릭터 고유: 귀살대 검사, 그림자 군단 등)
- 해상: 소형선(속도) / 중형선(균형) / 대형선(화력) + 거북선 등 캐릭터 고유 함선
- 상성 배율, 병종 스탯은 전부 `data/units/*.json` [MUST]

### 2.6 전투 시스템

**공통 원칙 [MUST]**: 전투는 Core 로직(§4)에서 **그래픽 없이 완결 계산 가능**해야 한다. UE5는 그 결과를 연출로 재생하는 레이어일 뿐이다.

#### 육상전
- 전장: 노드별 지형 타입 (평지/산악/삼림/시가지/공성) → 지형 버프·디버프 테이블 적용
- 진행: 턴제 전술. 부대 단위 이동/공격/스킬/대기
- 궁극기: 게이지(피해를 주고받을 때 충전) 100% 시 발동 가능. 발동 시 컷씬 트리거 → 광역 효과 적용
- 일기토 [MAY]: 무력 격차·조건 만족 시 발생하는 캐릭터 1:1 이벤트 전투
- 공성전: 성벽 레벨이 수비 측 버프. 공성병기로 성벽 게이지 파괴 후 본전투

#### 해상전
- 승패 변수 [MUST]: **풍향(8방위), 조류(순류/역류), 함선 업그레이드 상태**
  - 풍향: 바람을 등지면 이동력·화공 위력 상승, 맞바람이면 감소
  - 조류: 해역별 조류 방향 데이터. 순류 시 이동 +1, 역류 시 -1
- 행동: 함포 사격(원거리) / 백병전·승선(인접 시, 무력 스탯 기반) / 화공(풍향 의존)
- **상륙전**: 항구 간선을 통해 함대가 육상 영지 공격 시, 첫 2턴간 상륙 부대 방어 디버프(-25%) — 수비 측 이점 [MUST]

#### 전투 위임 [SHOULD]
- 매 전투를 수동으로 하면 늘어진다. **자동 계산(Auto-Resolve)** 옵션 제공: 양측 전투력 종합 수식으로 즉시 결과 산출. 중요 전투만 수동 전술 진입

## 4. OOP 아키텍처 설계 (Architecture)

### 4.1 레이어 분리 [MUST]

```
┌─────────────────────────────────────┐
│  Presentation Layer (UE5 / 콘솔UI)  │  ← 렌더링·입력·연출·사운드만
├─────────────────────────────────────┤
│  Core Simulation Layer (순수 C#)    │  ← 게임 규칙·상태·연산 전부
├─────────────────────────────────────┤
│  Data Layer (JSON 로더·검증)        │  ← 스키마 검증 포함
└─────────────────────────────────────┘
```

- **의존 방향은 위→아래 단방향** [MUST]. Core가 Presentation을 참조하면 리젝
- Core → Presentation 통신은 **이벤트 버스**(§4.3)로만. Core는 "무슨 일이 일어났는지" 발행할 뿐, 어떻게 보여줄지 모른다

### 4.2 핵심 클래스 명세 [MUST]

단일 책임 원칙(SRP): 클래스 하나 = 책임 하나. 아래 표를 기준으로 하되, 책임이 커지면 분리를 제안하라.

| 클래스 | 책임 (이것만 한다) | 핵심 멤버 |
|---|---|---|
| `GameManager` | 게임 전체 상태·페이즈 흐름 관리 | `CurrentTurn`, `CurrentPhase`, `AdvancePhase()`, `CheckWinCondition()` |
| `TurnSystem` | 턴 순서·페이즈 전이 규칙 | `PhaseOrder`, `NextActor()` |
| `Faction` | 세력 단위 자원·외교상태·소유영지 | `Treasury`, `Food`, `TechLevel`, `OwnedProvinceIds`, `DiplomaticRelations`, `DeclareWar()`, `FormAlliance()` |
| `Province` (추상) → `LandProvince`, `SeaZone` | 개별 노드의 내정·방어 데이터 | `Population`, `DefenseLevel`, `Facilities`, `Produce()`, `AdjacentNodeIds` |
| `Character` | 무장 스탯·소속·스킬·성장 | `Stats`, `Level`, `Loyalty`, `Skills`, `GainExp()` — **파생 클래스 금지, 데이터로 차별화** (§5.2) |
| `Army` / `Fleet` | 부대·함대 편성 상태 (지휘관+병종+병력수) | `CommanderId`, `Units`, `Morale`, `Supply`, `Move()` |
| `CombatManager` | 전투 준비·턴 진행·승패 판정 오케스트레이션 | `StartBattle()`, `ResolveAuto()`, `EndBattle()` |
| `DamageCalculator` | 데미지 공식 **순수 함수** 모음 (상태 없음) | `CalculateDamage(attacker, defender, terrain, weather)` |
| `SkillSystem` | 스킬 게이지·발동 조건·효과 적용 | `ChargeGauge()`, `ExecuteSkill()` — 효과는 EffectType 해석기로 처리 |
| `DiplomacyManager` | 외교 제안·수락·관계도 변화 | `ProposeAlliance()`, `TransferResources()` |
| `AIController` | AI 세력 의사결정 (세력당 1개) | `DecideTurnActions()` — 초기엔 규칙 기반 우선순위 스코어링 [SHOULD] |
| `EventBus` | Core→Presentation 이벤트 발행/구독 | `Publish<T>()`, `Subscribe<T>()` |
| `DataLoader` | JSON 로드·스키마 검증·인메모리 캐시 | `LoadCharacters()`, `Validate()` |
| `SaveSystem` | 게임 상태 직렬화/역직렬화 | `Save(slot)`, `Load(slot)` — 세이브는 JSON [SHOULD] |
| (UE5) `EffectPoolManager` | 투사체·파티클 오브젝트 풀 | `Spawn(key)`, `Return(obj)` (§6.1) |
| (UE5) `AudioManager` | BGM·SFX 재생, 기후·상황별 트랙 전환 | `PlayBgm(context)`, `PlaySfx(key)` |

### 4.3 이벤트 주도 규칙 [MUST]

- Core는 `BattleStarted`, `SkillExecuted(characterId, skillId, targets)`, `ProvinceCaptured`, `TurnEnded` 같은 **불변 이벤트 객체**를 발행
- 콘솔 UI는 이벤트를 텍스트 로그로, UE5는 같은 이벤트를 컷씬·파티클로 표현 → **동일 Core로 두 프런트엔드 구동 검증** (Phase 2의 콘솔이 곧 테스트 하네스)

### 4.4 금지 사항 [MUST]

- God Class 금지: `GameManager`에 전투 공식·내정 공식을 넣지 않는다
- 전역 static 상태·싱글턴 남용 금지 (EventBus·DataLoader는 DI로 주입)
- 캐릭터/스킬별 분기 하드코딩 금지: `if (character.Name == "이순신")` 류는 즉시 리젝
- Core 레이어에서 랜덤 사용 시 **시드 주입 가능한 Random 하나만** 사용 (리플레이·테스트 재현성)

## 5. 데이터 주도 설계 — JSON 스키마 [MUST]

**모든 밸런스 수치·콘텐츠 정의는 `data/` 폴더의 JSON으로 관리한다. 코드 하드코딩 절대 금지.** 밸런스 패치·아들과의 캐릭터 추가 놀이("우리 캐릭터 만들자")가 JSON 편집만으로 가능해야 한다.

```
data/
├── characters/characters.json
├── skills/skills.json
├── units/land_units.json, naval_units.json
├── map/world_map.json
├── factions/factions.json
├── terrain/terrain_modifiers.json
└── config/game_rules.json        ← 세율·상성배율·상륙디버프 등 전역 상수
```

### 5.1 Character 스키마

```json
{
  "id": "yi_sunsin",
  "name_ko": "이순신",
  "origin": "history_korea",
  "rarity": 5,
  "stats": { "ldr": 105, "str": 82, "int": 95, "pol": 70, "cha": 88, "nav": 120 },
  "growth_rates": { "ldr": 1.2, "str": 0.8, "int": 1.0, "pol": 0.6, "cha": 0.7, "nav": 1.5 },
  "passive_skill_id": "undefeated_admiral",
  "ultimate_skill_id": "crane_wing_formation",
  "unique_unit_id": "geobukseon",
  "start_faction": "player_selectable",
  "voice_set": "cc0_male_kr_01",
  "portrait_asset": "portraits/yi_sunsin.png"
}
```

### 5.2 Skill 스키마 — EffectType 조합 방식

스킬 효과는 아래처럼 **범용 효과 타입의 배열**로 정의한다. 새 캐릭터 스킬 추가 = JSON 추가만으로 끝나야 한다.

```json
{
  "id": "crane_wing_formation",
  "name_ko": "학익진",
  "type": "ultimate",
  "gauge_cost": 100,
  "cutscene_id": "cs_crane_wing",
  "conditions": [{ "type": "battle_domain", "value": "naval" }],
  "effects": [
    { "type": "aoe_damage", "target": "enemy_front_row", "power": 250, "scaling_stat": "nav" },
    { "type": "buff", "target": "ally_all", "stat": "morale", "amount": 20, "duration_turns": 3 }
  ]
}
```

지원 EffectType(초기 세트): `aoe_damage`, `single_damage`, `buff`, `debuff`, `shield`, `heal`, `summon_unit`, `terrain_change`, `gauge_drain`. 새 타입이 필요하면 **타입 추가를 먼저 제안**하고 해석기(SkillSystem)에 1회 구현 → 이후 데이터로 재사용.

### 5.3 Province 스키마

```json
{
  "id": "hanseong",
  "type": "land",
  "name_ko": "한성",
  "region": "east_asia",
  "terrain": "urban",
  "population": 180000,
  "base_production": { "gold": 120, "food": 90 },
  "facility_slots": 4,
  "defense_level": 3,
  "adjacent": ["pyongyang", "busan", "sea_yellow"],
  "port": true,
  "climate": "temperate"

```

### 5.4 map / faction / config

- `world_map.json`: 노드 목록 + 간선 목록(`{"from","to","type":"land|sea|port"}`)
- `factions.json`: 시작 세력, 시작 영지, AI 성향(`aggressive|defensive|expansionist`), 난이도 보정치
- `game_rules.json`: 상성 배율, 상륙 디버프 -25%, 동맹 자원지원 턴당 상한, 궁극기 게이지 충전량 등 **§2의 모든 매직넘버**

### 5.5 데이터 검증 [MUST]

- `DataLoader`는 로드 시점에 검증: 필수 필드 누락, 참조 무결성(존재하지 않는 skill_id·adjacent id), 스탯 범위(1~120) 위반 시 **어떤 파일 몇 번째 항목이 왜 틀렸는지** 명시하고 기동 실패
- 검증 실패를 조용히 스킵하는 코드는 리젝

## 6. 성능·최적화 지침 (Performance) [MUST]

목표: **미들레인지 데스크탑(GTX 1660급)에서 글로벌 맵 60fps, 전투 씬 60fps.**

### 6.1 오브젝트 풀링 (UE5 Phase)
- 투사체(화살·총알·마법), 파티클 이펙트, 데미지 텍스트는 `Spawn/Destroy` 반복 금지 → `EffectPoolManager`에서 대여/반납
- 풀 크기는 `config/pool_sizes.json`으로 외부화. 풀 고갈 시 경고 로그 + 임시 확장(런타임 크래시 금지)

### 6.2 LOD (Level of Detail)
- 글로벌 맵 줌아웃: 영지 = 간략 아이콘 + 세력 색상만. 물결·날씨·성 디테일 렌더링 OFF
- 줌인: 거리 기반 단계적 활성화 (UE5 Nanite/World Partition 활용 [MAY])
- 전투 씬: 화면 밖 유닛 애니메이션 틱 중지

### 6.3 Core 로직 성능
- 턴 해결 연산(전 세력 수입·AI 의사결정)은 **전체 노드 순회 1회 이내**로 설계. 노드별 중첩 전체 탐색(O(N²)) 금지
- 경로 탐색은 A* + 결과 캐시(맵 불변 구간)
- AI 세력 의사결정은 세력당 시간 예산(예: 50ms)을 두고 초과 시 휴리스틱 컷 [SHOULD]

### 6.4 데이터 주도(§5)는 최적화 규칙이기도 하다
- 밸런스 수정 때마다 리컴파일 없음 → 반복 개발 속도 = 성능

## 7. AI 협업 개발 파이프라인 (Phases) [MUST]

**각 Phase는 완료 기준(DoD)을 전부 통과해야 다음으로 넘어간다.** AI에게는 항상 "현재 Phase"를 명시하고 지시한다.

### Phase 0 — 데이터 구조·Core 골격 (예상: 첫 작업)
- **작업**: §5 JSON 스키마 확정 → 샘플 데이터 작성(캐릭터 10, 영지 12, 해역 3, 스킬 10) → `DataLoader` + 도메인 클래스(Faction/Province/Character/Army) + 단위 테스트
- **DoD**:
  - [ ] `dotnet test` 전체 통과 (로더 검증 케이스 포함: 깨진 참조·범위 위반 검출 테스트)
  - [ ] 샘플 JSON 로드 → 콘솔에 세력·영지·캐릭터 요약 출력
- **지시 예시**: *"Phase 0. §5.1~5.5 스키마대로 data/ 샘플과 DataLoader, 도메인 클래스, xUnit 테스트를 작성하라. 전투·UI 코드는 금지."*

### Phase 1 — 글로벌 맵·내정 시뮬레이터 (전투 제외)
- **작업**: 턴 루프(§2.2, 전투는 스텁) + 자원 생산 + 시설 건설 + 징병 + 부대 이동(A*) + 무혈 점령(수비대 0 영지) + 핫시트 2인 입력 + 세이브/로드
- **DoD**:
  - [ ] 콘솔에서 아빠·아들 2인이 턴 넘기며 자원 모으고 빈 영지 점령 가능
  - [ ] 50턴 자동 진행 스모크 테스트 통과 (예외·자원 음수 없음)
  - [ ] 세이브 → 로드 → 상태 동일성 테스트 통과

### Phase 2 — 전투 로직·스킬·외교·AI (콘솔 완결판)
- **작업**: `CombatManager`·`DamageCalculator`(지형·상성·풍향·조류) + `SkillSystem`(EffectType 해석기, 게이지) + 육상/해상/상륙전 + 자동 계산 + `DiplomacyManager`(동맹·시야공유·자원지원·공동전투) + 규칙 기반 `AIController` + 승리 판정
- **DoD**:
  - [ ] 학익진·마슈 방패 등 스킬 5종 이상이 콘솔 로그로 수치 변화 검증됨
  - [ ] 해상전에서 풍향·조류 변경 시 결과가 달라지는 테스트 통과
  - [ ] **부자 2인이 콘솔 버전으로 처음부터 공동 승리까지 1회 완주** ← 재미 검증 게이트
  - [ ] 밸런스 배치 시뮬: AI끼리 100판 자동 대전 → 특정 세력 승률 70% 초과 없음 [SHOULD]
- **★ 게이트 리뷰**: 완주 후 "UE5 풀 3D 강행 / Godot·2D 축소 / 콘솔+간이UI 유지" 재결정 (§9)

### Phase 3 — UE5 연동·비주얼
- **작업**: UE5 프로젝트 생성, Core C# 로직 이식(C++ 포팅 또는 명세 기준 재구현 — 콘솔판이 기대값 오라클) + 글로벌 맵 3D(LOD) + 전투 씬 + 궁극기 컷씬·파티클(오브젝트 풀) + UI/UX

  - [ ] 동일 시드·동일 입력 시 UE5 판과 콘솔 판의 전투 결과 일치 (오라클 테스트)
  - [ ] GTX 1660급 60fps (맵·전투 모두), 풀링 미적용 Spawn/Destroy 검출 0건

### Phase 4 — CC0 사운드·에셋·폴리시

## 10. 용어집

| 용어 | 정의 |
|---|---|
| 노드(Node) | 맵의 최소 단위 (육상 영지 또는 해상 거점) |
| 핫시트(Hot-seat) | 한 PC에서 플레이어가 교대로 턴을 진행하는 로컬 멀티 방식 |
| 궁극기 게이지 | 전투 중 충전되어 100%에 궁극기 발동을 허용하는 자원 |
| 오라클 테스트 | 콘솔판 결과를 정답지 삼아 UE5판 로직 일치를 검증하는 테스트 |
| DoD | Definition of Done. Phase 완료 판정 체크리스트 |
| EffectType | 스킬 효과를 데이터로 조립하기 위한 범용 효과 단위 |
